# signal-trader

Читает сигналы из Telegram-канала [@hardcoretrading](https://t.me/hardcoretrading) от имени вашего аккаунта и открывает по ним фьючерсные позиции на Bybit (USDT-перпетуалы) со стопом и тейком. Есть бэктест по истории канала.

```
Telegram (ваш аккаунт, GramJS) → parser → strategy (вход, размер, плечо) → Bybit V5 (ордер + TP/SL)
                                                                 ↑
                                        monitor каждые 30 с: исполнение, таймаут, закрытие → уведомления
```

## Результаты на истории канала (сент. 2025 — сент. 2026)

Цены взяты со спота Binance, свечи 5 минут. Если свеча задела и стоп, и тейк, считается стоп. Комиссия taker 0.055% на вход и на выход. В расчёт вошли 298 из 349 сигналов: остальных монет нет на споте Binance.

| Правила | Сделок | Винрейт | Итог | При риске 1% | Макс. просадка |
|---|---|---|---|---|---|
| Как в канале: вход сразу, цель и стоп канала | 292 | 76% (нужно 80%) | **−15.7R** | −15% | 22% |
| Оптимизированные (по умолчанию) | 138 | 43% (нужно 36%) | **+23.4R** | +24% | 17% |

По трём периодам по 4 месяца: «как в канале» в минусе во всех трёх (−4.2R / −7.3R / −4.2R), оптимизированные правила в плюсе во всех трёх (+7.0R / +6.3R / +10.0R).

Преимущество слабое: t-статистика около 1.2, и найдено оно перебором 2100 вариантов. Это гипотеза для проверки на демо-счёте, а не доказанная прибыльность.

## Как торгует

| Шаг | Правило (параметры в `.env`) |
|---|---|
| Уровни | Все уровни отсчитываются от худшей границы зоны: верхней для лонга, нижней для шорта. Там обычно и стоит цена в момент публикации. |
| Вход | Лимитный ордер на `ENTRY_FRAC` вглубь зоны (0.75). Если цена уже там или лучше — рыночный ордер. Через `ENTRY_TIMEOUT_MIN` минут (240) ордер отменяется; отменяется и раньше, если цена ушла к цели без нас. |
| Цель и стоп | Дистанция от худшей границы, умноженная на коэффициент: цель `TP_MULT`×(3), стоп `SL_MULT`×(0.75) от значений канала. Ставятся в том же ордере (`tpslMode=Full`). |
| Безубыток | Когда цена прошла `BREAKEVEN_AT` пути до цели (0.5), стоп переносится на цену входа плюс комиссии. |
| Размер позиции | Если сработает стоп, теряется `RISK_PER_TRADE_PCT`% капитала с учётом комиссий. |
| Плечо | Наименьшее из: плечо канала, `MAX_LEVERAGE`, максимум биржи и значение, при котором ликвидация в `LIQ_BUFFER` раз дальше стопа. |
| Фильтры | `MAX_OPEN_POSITIONS`, одна сделка на монету, дневной лимит убытка, `TRADE_TYPES`, `COIN_BLACKLIST`, сигнал не старше `MAX_SIGNAL_AGE_SEC`. |
| Символ | Бот ищет `TRUMPUSDT`, `1000TRUMPUSDT` и т. п. и сверяет цену с сигналом. Если расхождение больше 35%, сигнал пропускается. |

## Запуск по шагам

```bash
cd artifacts/signal-trader
pnpm install
cp .env.example .env
```

1. **Telegram API.** На https://my.telegram.org → API development tools получите `api_id` и `api_hash` и впишите их в `.env`.
2. **Вход в аккаунт.** Выполните `pnpm login`: введите телефон, код и пароль 2FA. Выведенную строку вставьте в `TG_SESSION`. Эта строка даёт полный доступ к аккаунту, храните её как пароль.
3. **Бэктест.** Выполните `pnpm backtest --source telegram --days 180` (подробнее ниже).
4. **Dry run.** Оставьте `DRY_RUN=true` и выполните `pnpm start`. Бот будет присылать, что сделал бы, но ордера отправлять не будет.
5. **Demo-счёт Bybit.** Демо-торговля идёт по реальным ценам на виртуальные деньги. Создайте в ней API-ключ (Bybit → Demo Trading → API), затем задайте `BYBIT_ENV=demo` и `DRY_RUN=false`. Гоняйте так 2–4 недели.
6. **Реальный счёт.** Задайте `BYBIT_ENV=mainnet` и начинайте с маленького депозита и `RISK_PER_TRADE_PCT=0.5`. Ключ создавайте только с правом Contract Trade, без вывода средств и с привязкой к IP сервера. В настройках аккаунта включите One-Way Mode и Isolated Margin.

Уведомления: создайте бота через @BotFather, напишите ему что-нибудь, а свой chat id узнайте у @userinfobot. Затем заполните `NOTIFY_BOT_TOKEN` и `NOTIFY_CHAT_ID`.

## Бэктест

```bash
pnpm backtest --source telegram --days 180            # через вашу сессию (подходит и для закрытых каналов)
pnpm backtest --source web --days 180                 # публичная веб-версия t.me/s/…, без логина
pnpm backtest --source export --file result.json      # Telegram Desktop → Экспорт истории чата → JSON
```

Если Bybit недоступен из вашей страны или с сервера, добавьте `--prices binance` (в облачных окружениях с прокси может понадобиться `NODE_USE_ENV_PROXY=1`): тогда берутся спотовые цены с публичного API Binance, они почти совпадают с фьючерсными.

Скачать историю канала и посмотреть статистику сигналов без цен: `pnpm history --days 365`. Команда сохраняет `data/history.json`, его потом можно передать в `pnpm backtest --source export --file data/history.json`.

Подбор правил: `pnpm optimize --dataset data/backtest/dataset.json --split 2026-03-28`. Датасет пишет `pnpm backtest`. Правила выбираются на истории до даты `--split` и проверяются на истории после неё.

Опции: `--interval 1|5|15` — таймфрейм свечей в минутах (по умолчанию 5), `--hold-days 7` — через сколько дней закрывать сделку по таймауту. Все параметры стратегии берутся из `.env`, их можно менять и перезапускать бэктест.

Что выводится:
- винрейт и винрейт, нужный для безубытка;
- средний результат в R, где 1R — убыток на стопе;
- profit factor, итог и максимальная просадка при заданном риске;
- сколько раз плечо канала ликвидировало бы позицию раньше стопа;
- разбивка по LONG и SHORT, по типу сделки и по месяцам.

Детали по каждой сделке записываются в `data/backtest/trades.csv`.

Допущения бэктеста:
- вход по открытию первой свечи после публикации;
- если свеча задела и стоп, и тейк, считается стоп;
- комиссия taker 0.055% на вход и на выход;
- проскальзывание и фандинг не учитываются.

## Что ещё не сделано

- **Служебные сообщения канала.** Посты вроде «закрываем», «отмена» или «стоп в безубыток» бот только пересылает вам, если в них упоминается открытая монета. Чтобы обрабатывать их автоматически, нужны примеры таких сообщений.
- **Несколько целей.** Позиция закрывается целиком по первой цели.
- **Хранилище.** Состояние хранится в `data/state.json`. Этого хватает для одного процесса; при желании можно перенести в Postgres из `lib/db`.
